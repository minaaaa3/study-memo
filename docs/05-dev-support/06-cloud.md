# 5-6. クラウドコンピューティング

## 例え話：賃貸マンション vs 持ち家

サーバーを持つ方法は、住む場所を選ぶのに似ています。

- **持ち家（自社サーバー）**: 全部自分で管理。自由だけど大変
- **賃貸マンション（クラウド）**: 必要な分だけ借りる。管理は大家さんにお任せ

クラウドにも種類があります：
- **部屋だけ借りる（IaaS）**: 自分で家具を揃える
- **家具付きで借りる（PaaS）**: すぐ住める
- **ホテルに泊まる（SaaS）**: 全部お任せ

---

## 核心：なぜクラウドを使うのか

### 自社サーバーの大変さ

自分でサーバーを持つと、こんなことを全部やる必要があります：

- サーバーを買う（数十万円〜）
- 設置場所を確保する（電気代、冷房代）
- OSをインストールする
- セキュリティパッチを当てる
- 24時間監視する
- 壊れたら修理する
- アクセスが増えたらサーバーを追加する

### クラウドなら

- 必要な時に、必要な分だけ借りる
- 管理はクラウド会社がやってくれる
- 使った分だけ支払う
- アクセスが増えたら自動で増やせる

---

## クラウドの3つのレベル

「どこまで自分でやるか」で3種類に分かれます。

| 種類 | 何をするか | 例 | こんな人向け |
|------|-----------|-----|------------|
| **IaaS** | サーバーを借りて、自分でセットアップ | AWS EC2, GCP | インフラに詳しい人 |
| **PaaS** | コードを置くだけで動く | Vercel, Railway | アプリ開発に集中したい人 |
| **SaaS** | 完成したサービスを使う | Gmail, Slack | エンドユーザー |

### 例え話で理解する

| 種類 | 例え | 何を自分でやる？ |
|------|------|----------------|
| IaaS | 土地を借りて家を建てる | 設計、建築、家具、全部 |
| PaaS | 家具付きマンション | 荷物を持ち込むだけ |
| SaaS | ホテル | チェックインするだけ |

### Web開発者が使うのは主に PaaS

IaaS は難しいし、SaaS は「使うだけ」なので、Web開発者は **PaaS** を使うことが多いです。

```text
PaaS を使うと...

1. コードを書く
2. Git で push する
3. 自動でデプロイされる
4. 動く！

サーバーの設定は不要！
```

## 初心者におすすめのサービス

### フロントエンドを公開したい → Vercel / Netlify

Next.js や React のアプリを簡単に公開できます。

| サービス | 特徴 | 無料枠 |
|---------|------|-------|
| **Vercel** | Next.js と相性抜群、超簡単 | 個人利用なら十分 |
| **Netlify** | 静的サイトに強い | 個人利用なら十分 |

```text
Vercel でデプロイする流れ:

1. GitHub にコードを push
2. Vercel と GitHub を連携
3. 自動でビルド＆デプロイ
4. URL が発行される（例: my-app.vercel.app）

以降、push するたびに自動更新！
```

### バックエンドを動かしたい → Railway / Render

Node.js や Python のサーバーを動かせます。

| サービス | 特徴 | 無料枠 |
|---------|------|-------|
| **Railway** | シンプル、DB も簡単に追加 | 月5ドル分 |
| **Render** | 無料枠が大きい | 静的サイトは無制限 |

### データベースを使いたい → Supabase / PlanetScale

| サービス | 種類 | 特徴 |
|---------|------|------|
| **Supabase** | PostgreSQL | 認証機能も付いてる、Firebase の代替 |
| **PlanetScale** | MySQL | Git のようにブランチで管理できる |
| **MongoDB Atlas** | MongoDB | JSON 形式でデータを保存 |

### 認証を追加したい → Clerk / Auth0

ログイン機能を自分で作るのは大変です。認証サービスを使えば簡単に追加できます。

| サービス | 特徴 |
|---------|------|
| **Clerk** | Next.js との相性が良い、UI がきれい |
| **Auth0** | 高機能、企業でも使われる |
| **Firebase Auth** | Google ログインが簡単 |

## 大手クラウド（AWS / GCP / Azure）

大きな会社や本格的なサービスでは、大手クラウドを使います。

### AWS（Amazon Web Services）

一番人気。サービスの種類がとても多い。

| サービス名 | 何ができる |
|-----------|-----------|
| EC2 | 仮想サーバーを借りる |
| S3 | ファイルを保存する |
| RDS | データベースを使う |
| Lambda | サーバーレス関数 |
| CloudFront | CDN（高速配信） |

### Google Cloud Platform（GCP）

データ分析や機械学習に強い。Firebase が人気。

| サービス名 | 何ができる |
|-----------|-----------|
| Compute Engine | 仮想サーバー |
| Cloud Storage | ファイル保存 |
| Cloud SQL | データベース |
| Cloud Run | コンテナを動かす |
| Firebase | バックエンド全部入り |

### Microsoft Azure

Windows や Microsoft 製品との連携に強い。

| サービス名 | 何ができる |
|-----------|-----------|
| Virtual Machines | 仮想サーバー |
| Blob Storage | ファイル保存 |
| Azure SQL | データベース |
| Azure Functions | サーバーレス関数 |

### 初心者は大手クラウドを使うべき？

**最初は使わなくて大丈夫です。**

- Vercel + Supabase で十分なことが多い
- AWS は設定が複雑で挫折しやすい
- 大規模になってから検討すればOK

## サーバーレスとは

### 「サーバーがない」わけではない

サーバーレスは「サーバーを意識しない」という意味です。

```text
従来のサーバー:
- 24時間動いている
- 使っていない時間も料金がかかる
- アクセスが増えたら自分で増やす

サーバーレス:
- リクエストが来た時だけ動く
- 使った分だけ料金がかかる
- 自動でスケールする
```

### 具体例：Vercel の API Routes

Next.js で API を作ると、自動でサーバーレスになります。

```typescript
// app/api/hello/route.ts
export async function GET() {
  return Response.json({ message: "Hello!" });
}
```

これだけで `/api/hello` という API ができます。Vercel が勝手にサーバーを用意してくれます。

### サーバーレスの注意点

| 注意点 | 説明 |
|--------|------|
| コールドスタート | 初回リクエストは少し遅い（起動に時間がかかる） |
| 実行時間制限 | 長い処理は向いていない（Vercel は最大60秒） |
| 状態を持てない | データは DB やキャッシュに保存する必要がある |

## Docker とは

### 環境を丸ごとパッケージ

「自分のPCでは動くのに、サーバーでは動かない」という問題を解決します。

```text
Docker なし:
- 自分のPC: Node.js 20 が入ってる
- サーバー: Node.js 18 しかない
- → 動かない！

Docker あり:
- Node.js 20 を含んだ「箱」を作る
- その「箱」ごとサーバーに送る
- → どこでも同じように動く！
```

### 初心者は Docker を使うべき？

**最初は不要です。**

- Vercel や Railway は Docker なしでデプロイできる
- 複数人開発や複雑な環境で必要になる
- 「環境が合わない」問題が起きたら検討

## 料金について

### 無料枠を活用しよう

ほとんどのサービスに無料枠があります。個人開発なら無料で十分なことが多いです。

| サービス | 無料枠 |
|---------|-------|
| Vercel | 個人利用は無料 |
| Netlify | 月100GBまで無料 |
| Supabase | 2プロジェクトまで無料 |
| PlanetScale | 1DBまで無料 |
| Railway | 月5ドル分無料 |

### 課金の仕組み

```text
従量課金（使った分だけ）:
- メリット: 使わなければ0円
- デメリット: 急にアクセスが増えると高額に

固定課金（月額）:
- メリット: 予算が読みやすい
- デメリット: 使わなくても払う
```

### 請求が怖い場合

- **アラートを設定**: 一定額を超えたら通知
- **上限を設定**: それ以上使えないようにする
- **無料枠で始める**: 有料プランは必要になってから

## 選び方のガイド

### 個人開発・学習

```text
おすすめ構成:
├── フロントエンド: Vercel（無料）
├── バックエンド: Next.js API Routes（Vercel で一緒に動く）
├── データベース: Supabase（無料）
└── 認証: Clerk または Supabase Auth

月額: 0円で始められる！
```

### 小規模サービス（ユーザー数百人）

```text
おすすめ構成:
├── フロントエンド: Vercel Pro
├── バックエンド: Railway または Render
├── データベース: Supabase Pro または PlanetScale
└── ファイル保存: Cloudflare R2

月額: 数千円〜
```

### 中〜大規模サービス

```text
検討すべきこと:
├── AWS / GCP / Azure の利用
├── 専門のインフラエンジニア
├── 監視・アラートの仕組み
└── 障害対応の体制

→ このレベルになったら専門家に相談
```

## よくある誤解

### 「クラウドは高い」？

**小規模なら無料〜数千円で十分です。**

- 無料枠で個人開発は十分
- 使った分だけの従量課金
- 自社サーバーの電気代・人件費と比較すると安いことも

### 「AWS を覚えないとダメ」？

**最初は Vercel + Supabase で十分です。**

- AWS は設定が複雑
- 小規模サービスには過剰
- 必要になってから学べばOK

### 「サーバーレスなら何でも解決」？

**向き不向きがあります。**

| 向いている | 向いていない |
|-----------|-------------|
| API エンドポイント | 長時間の処理 |
| 定期実行タスク | リアルタイム通信（WebSocket） |
| 画像のリサイズ | 初回の速度が重要なもの |

### 「Docker / Kubernetes を使うべき」？

**ほとんどの場合、不要です。**

- PaaS（Vercel, Railway）なら Docker 不要
- Kubernetes は大企業向け
- 「かっこいいから」で選ばない

---

## まとめ

- **クラウド** = サーバーを借りて使う仕組み
- **IaaS / PaaS / SaaS** = 自分でやる範囲の違い
- **初心者は PaaS** = Vercel, Railway, Supabase など
- **無料枠を活用** = 個人開発なら0円で始められる
- **AWS は後回し** = 必要になってから学ぶ
- **シンプルに始める** = 最初から複雑にしない

## 最初の一歩

1. **Vercel アカウントを作る**
   - GitHub と連携するだけ
   - Next.js アプリを push すると自動デプロイ

2. **Supabase アカウントを作る**
   - データベースが無料で使える
   - 認証機能も付いてくる

3. **簡単なアプリを公開してみる**
   - 動くものを作ることが大事
   - 完璧を目指さない

```text
初心者の目標:
「自分のアプリを URL で公開できた！」

これができれば、クラウドの基本は OK です。
```
